EVALUATION

Booth Attendance, Evaluation & E-Certificate System

A web app that took a whole skills demonstration off paper. Participants check in with a one-time passkey, answer a short evaluation before and after the demo, and leave with a PDF certificate that has their name on it. Organizers watch the results come in live.

1.Overview

The 4th Year IT students ran a Service Learning Competency booth with three hands-on demos: UTP Cable Termination, Router and Wi-Fi Configuration and Basic Network Troubleshooting. Every visitor had to be logged, evaluated before and after their demo, and given a certificate of participation.

Doing that on paper means stacks of forms, manual tallying and hand-writing certificates afterwards. This system does all of it from a phone. Visitors scan a QR code at the booth, and organizers get a live dashboard and a spreadsheet they can export to Excel.

It runs entirely on free services. The site is hosted on GitHub Pages, and the data lives in a Google Sheet behind a Google Apps Script web app. There's no server to pay for or maintain.

2.Participant Flow

Five steps across two visits to the same page. Booth staff hand out a passkey slip, and the visitor uses it at the start and again at the end.

  2. 2before

  3. 3before

  4. 4after

    Same passkey again. Ten rating questions about the session and two optional comments.

  5. 5after

    A PDF certificate for that topic, with their name, downloads automatically.

3.Passkeys

Each participant gets one passkey from the booth staff. It is what makes this work without accounts or logins. It ties the before and after answers to one person, decides which certificate they get, and makes sure each visitor counts once.

K7M-Q3P

Unused

Generated by an organizer for one topic and printed on a cut-out slip.

→
K7M-Q3P

Started

Attendance and pre-evaluation saved. The key now opens the post-evaluation.

→
K7M-Q3P

Used

Post-evaluation saved and certificate issued. The key is finished.

  • Keys use 32 characters with no 0, O, 1 or I, so nobody misreads a slip.
  • The topic always comes from the Keys sheet, never from the browser, so nobody can claim another topic's certificate.
  • A wrong key gets an 800 ms delay before the reply to slow down guessing.
  • Keys for a closed topic are turned away until an organizer opens it again.

6.Reliability Under Load

The hard part was the moment a demo ends and a whole group submits at once. Google Sheets isn't a real database, so the saving logic was stress-tested and changed until every row came through correctly.

  1. 1

    Save in parallel with a short lock dropped

    Faster on paper, but simultaneous writes to the sheet lost some rows and doubled others under load.

  2. 2

    Faster key lookup with TextFinder dropped

    Under heavy load it sometimes returned the wrong row. The backend went back to reading the whole Keys sheet, which is slower but always right.

  3. 3

    One at a time, and the browser retries kept

    Each submission takes the script lock, checks the key, appends the row and marks the key used. If the lock is busy the server answers "busy" and the phone tries again. This stayed 100% correct with 100 simultaneous submissions.

6.1 Client retry timing

Waits grow after each busy reply, and each one is randomized between 60% and 140% so a crowd doesn't retry at the same instant. Any request still waiting after 45 seconds is cancelled and retried.

A retry can find its own earlier attempt already saved. The app treats "already used" on a retry as success, so nobody sees an error for an answer that actually went through.

7.Security

The website's code is sent to every visitor's browser, so nothing secret can live in it.

  • The admin password is checked by Google's servers and stored in Script Properties. It never appears in the website code.
  • The public backend URL can only submit answers, and only with an unused key for an open topic. Reading results needs the password.
  • The script asks for access to its own spreadsheet only, and nothing else in the organizer's Google Drive.
  • Text that starts with =, +, - or @ is escaped before it's saved, so a "name" can't run as a spreadsheet formula.
